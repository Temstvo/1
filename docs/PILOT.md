# Пилот: один управляемый сервер, один тариф

Это текущая инструкция запуска. Старые Compose-файлы для Oracle, отдельные landing/admin/Telegram-приложения и старые tag-based CD workflows не входят в пилот. Используются `docker-compose.prod.yml`, backend и frontend; администрирование находится на `/admin`, поддержка — на `/support`.

## Состояние

Код проверяется локально с настоящей PostgreSQL и заменителями платёжного/VPN-провайдеров. Это не доказательство боевого платежа или работающего туннеля. На рабочем компьютере не установлен Docker, а Marzban, ЮKassa и почта не настроены. Внешнее развёртывание требует домена и доступа оператора к VPS.

Пилотный тариф: **Appi, 30 дней, 50 ГиБ, 499 ₽** — исходные параметры для проверки, не расчёт прибыльности. `PILOT_PRICE_RUB` и `PILOT_TRAFFIC_GB` меняются до публикации. Продажи по умолчанию закрыты (`ENABLE_CHECKOUT=false`). `PILOT_MODE=true` скрывает импортированный каталог и разрешает покупку только одного тарифа. Старые подписки и оплаченные заказы сохраняются.

## 1. Подготовить один VPN-сервер

Нужен VPS под управлением оператора, на котором установлен Marzban/Xray. Используйте [официальную инструкцию Marzban](https://gozargah.github.io/marzban/en/docs/installation), [настройку Reality](https://gozargah.github.io/marzban/en/examples/all-on-one-port) и [API](https://gozargah.github.io/marzban/en/docs/api). Не подключайте к платному тарифу общие ключи из `serv-configs`.

- Один VLESS Reality inbound, например с тегом `APPI_REALITY`, транспорт TCP, flow `xtls-rprx-vision`.
- Настройте реальный адрес сервера в Host Settings: выданные ссылки должны содержать публичный адрес, корректные SNI, public key и short ID.
- API Marzban и subscription URL должны работать по HTTPS. Панель и Reality должны слушать разные порты/IP, если приложение размещается на том же VPS. Нельзя одновременно занять 443 двумя процессами.
- Создайте отдельные учётные данные панели для Appi. Задайте `MARZBAN_URL`, `MARZBAN_USERNAME`, `MARZBAN_PASSWORD`, `MARZBAN_INBOUND_TAG` в приватном `.env.production`.
- Сохраните резервную копию данных Marzban и ключей Reality отдельно от базы Appi. Старые ключи, опубликованные в истории Git, замените.

Appi создаёт персонального пользователя, передаёт конечный срок, квоту и `no_reset`. Продление сохраняет UUID и добавляет квоту. Окончание срока и исчерпание трафика ограничиваются на VPN-сервере; рабочий процесс Appi повторяет неудачные изменения и отключения. Ограничение одновременных устройств не реализовано и не должно обещаться покупателям.

## 2. Развернуть сайт

На Linux-хосте нужны Docker Engine с Compose v2, Node.js 22 и этот репозиторий. Направьте DNS домена на хост; откройте TCP 80/443 и порт VPN. У базы и backend нет опубликованных портов. Если Marzban расположен отдельно, VPN-порт открывается на его VPS.

```sh
node scripts/init-production-env.mjs
# Заполните приватный .env.production. Не коммитьте и не публикуйте его.
node scripts/ops.mjs deploy
node scripts/ops.mjs pilot-plan
node scripts/ops.mjs probe-vpn
node scripts/ops.mjs status
```

Генератор создаёт случайные ключи и отказывается перезаписывать существующий файл. Пароль PostgreSQL генерируется в hex, поэтому безопасен в URL. `VPN_ENCRYPTION_KEY` необходим также при восстановлении базы; храните его резервную копию. Caddy получает HTTPS-сертификат для `APP_DOMAIN`. Все браузерные запросы идут через same-origin BFF; наружу напрямую пропускаются только webhook и `/healthz`.

Для администратора временно задайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` (минимум 16 символов) в приватном файле и выполните:

```sh
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend node scripts/create-admin.cjs
```

Затем удалите `ADMIN_PASSWORD`. Команда не повышает права существующего пользователя. В `/admin` доступны управление доступом и история, `/support` показывает сотруднику очередь обращений. `/api/admin/readiness` возвращает состояние провайдеров и число ошибок VPN, зависших оплат и обращений без секретов.

## 3. Проверить оплату до открытия продаж

Настройте тестовый магазин ЮKassa. В кабинете провайдера укажите URL `https://ВАШ-ДОМЕН/api/payments/webhook/yookassa` и события `payment.succeeded`, `payment.canceled`, `refund.succeeded`. [Уведомления ЮKassa](https://yookassa.ru/developers/using-api/webhooks) и [возвраты](https://yookassa.ru/developers/payment-acceptance/after-the-payment/refunds).

Укажите ключи магазина, `YOOKASSA_TEST_MODE=true`, почтовый Resend и подтверждённый `EMAIL_FROM`, контакт поддержки и реальные реквизиты `OPERATOR_NAME` / `OPERATOR_DETAILS`. Настройки чеков, в том числе `YOOKASSA_VAT_CODE`, должен определить оператор по своему магазину. Страницы `/terms` и `/privacy` описывают работу приложения; оператор дополняет и проверяет их для своей деятельности и страны до боевых продаж.

Только после проверки конфигурации включите `ENABLE_CHECKOUT=true`, пересоздайте backend. Интерфейс явно показывает тестовый режим. После прохождения сценариев ниже замените тестовые ключи боевыми и установите `YOOKASSA_TEST_MODE=false`. Выполните одну реальную контрольную покупку и возврат. Тестовая покупка не подтверждает работу боевого магазина.

Возврат сначала оформляет оператор в кабинете ЮKassa. Appi не отправляет деньги автоматически. Подтверждённый webhook создаёт уникальную запись возврата и уменьшает оплаченный срок/квоту пропорционально сумме. Повторы не списывают срок дважды. Если уведомление потеряно, сотрудник может выполнить `POST /api/payments/refunds/ID-ВОЗВРАТА/reconcile`: данные заново проверяются через API ЮKassa. Частичный возврат отображается суммой, полный — статусом `REFUNDED`.

## 4. Приёмочный сценарий

| Проверка                                         | Ожидаемый результат                                                                               |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Открыть `/app` без регистрации                   | Видны инструкции и кабинет; общие ключи не выдаются                                               |
| Сохранить гостевой аккаунт                       | Email/пароль работают; данные остаются в том же аккаунте                                          |
| Подтвердить email и сбросить пароль              | Письма реально приходят; ссылка сброса одноразовая; старые сессии отозваны                        |
| Включить пробный доступ                          | Только подтверждённый аккаунт до первой подписки; 24 ч/1 ГиБ, повтор невозможен                   |
| Оплатить тариф                                   | Единственный заказ, единственная подписка; статус VPN сначала ожидающий, затем ACTIVE             |
| Повторить webhook                                | Срок и квота не удваиваются                                                                       |
| Импортировать ссылку на Android, iPhone, Windows | Реально проходит трафик, корректны DNS и маршрут; проверить Wi-Fi и мобильную сеть                |
| Продлить                                         | UUID сохраняется, добавляется 30 дней и квота                                                     |
| Исчерпать тестовую квоту / дождаться срока       | Сервер прекращает пропускать трафик; скачивание конфигурации также ограничено                     |
| Отозвать доступ в `/admin`                       | Уже импортированный ключ перестаёт работать после синхронизации                                   |
| Временно остановить Marzban                      | Оплата не теряется; ошибка и повторная попытка видны оператору                                    |
| Оформить возврат                                 | Проверена сумма, срок/квота уменьшаются один раз; полный возврат первой покупки прекращает доступ |
| Создать обращение                                | Только владелец и сотрудник видят переписку; сотрудник может ответить                             |
| Восстановить резервную копию отдельно            | Все таблицы и миграции читаются; рабочая база не изменена                                         |

Пробный доступ включается отдельно: `ENABLE_VPN_TRIAL=true`, `TRIAL_HOURS=24`, `TRIAL_TRAFFIC_GB=1`, `TRIAL_DAILY_LIMIT=50`. Проверка email и глобальный дневной бюджет уменьшают злоупотребления, но не доказывают уникальность человека. Гостевой просмотр остаётся доступным независимо от пробного VPN.

## 5. Резервное копирование и наблюдение

```sh
node scripts/ops.mjs backup
node scripts/ops.mjs verify-backup backups/НУЖНЫЙ-ФАЙЛ.dump
node scripts/ops.mjs status
```

Backup пишется с ограниченными правами, сначала `.partial`, затем переименовывается. Верификация восстанавливает его в отдельную временную БД и проверяет таблицы; рабочую базу не трогает. Копируйте успешные backup-файлы в защищённое хранилище вне VPS. Пароли/ключ шифрования и база Marzban требуют отдельных копий. Перед обновлением делайте backup. Откат приложения — предыдущий Git-коммит и пересборка; миграции автоматически назад не откатываются.

Замена рабочей БД — отдельная явная команда `node scripts/ops.mjs restore FILE --confirm-replace-appi`. Она останавливает backend, восстанавливает одной транзакцией, применяет миграции и запускает backend. При ошибке backend остаётся остановленным для расследования.

Настройте внешний монитор `https://ВАШ-ДОМЕН/healthz` с уведомлениями оператору и ежедневный запуск backup. Эти внешние задания ещё не созданы: место развёртывания и получатель уведомлений не предоставлены. `status` завершится с ошибкой при сбое БД, ошибках VPN или отставании синхронизации. Логи контейнеров ограничены по объёму.

## 6. Экономика одного тарифа

`scripts/pilot-economics.mjs` считает вклад одного клиента и число клиентов для покрытия фиксированных расходов. Все расходы, комиссии, налоги, возвраты, стоимость привлечения и срок удержания задаются оператором. Пример только для проверки формулы (не фактические тарифы провайдеров):

```sh
node scripts/pilot-economics.mjs '{"price":500,"fixedMonthly":3000,"variablePerUser":50,"feePercent":4,"taxPercent":6,"refundPercent":0,"acquisitionCost":100,"averagePaidMonths":2}'
```

Ожидается вклад 350 и 9 клиентов для покрытия 3000 фиксированных расходов. При неположительном вкладе безубыточность не вычисляется. Реальную цену определяйте после замера потребления трафика на пилотной группе.

## Проверки кода

```sh
pnpm --filter @appi/backend exec prisma generate
pnpm --filter @appi/backend build
pnpm --filter @appi/frontend build
pnpm --filter @appi/backend exec jest --runInBand
node --test scripts/tests/*.test.mjs
```

Интеграционные тесты требуют отдельной БД с именем, оканчивающимся на `_test`, `NODE_ENV=test`, ключей JWT и `VPN_ENCRYPTION_KEY`, применённых миграций и `RUN_DATABASE_TESTS=true`. Внешние провайдеры заменены контрактными двойниками. CI выполняет тесты и сборку контейнеров; успешный результат CI не заменяет проверку реального туннеля и платежа.

Локальная проверка 21.09.2026: обе production-сборки успешны; 79 backend-тестов (включая 8 сценариев с PostgreSQL), 3 проверки расчёта экономики и 16 офлайн-проверок вёрстки прошли. Сборка Docker и восстановление через Docker локально не запускались: Docker отсутствует. Боевые провайдеры, мобильные устройства и внешний монитор остаются этапом приёмки на сервере.
