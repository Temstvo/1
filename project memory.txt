# DATABASE MODELS

25+ models created in Prisma schema:

Auth & Users:
- User (id, email, passwordHash, role, status, emailVerified, twoFactorEnabled, referralCode)
- Profile (userId, firstName, lastName, avatar, country, language, phone, timezone)

Sessions & Devices:
- Session (userId, tokenHash, ip, userAgent, deviceName, isActive, expiresAt)
- Device (userId, name, platform, osVersion, lastIP, lastSeen)

Subscriptions & Plans:
- Plan (name, description, price, currency, duration, trafficLimit, deviceLimit, protocols, regions, features)
- Subscription (userId, planId, status, startedAt, expiresAt, autoRenew)

Payments & Invoices:
- Payment (userId, subscriptionId, provider, transactionId, amount, status)
- Invoice (userId, paymentId, number, subtotal, tax, total)

VPN & Servers:
- Server (name, country, city, ip, protocols, status, cpu, ram, load, latency)
- VPNConfig (userId, serverId, protocol, config, publicKey, privateKey)
- Connection (userId, serverId, deviceId, protocol, connectedAt, bytesReceived, bytesSent)
- TrafficUsage (userId, serverId, download, upload, date, hour)

Other:
- Coupon (code, type, value, maxUses, expiresAt)
- Referral (ownerId, userId, commission)
- Notification (userId, type, title, message, read)
- Ticket (userId, subject, status, priority)
- TicketMessage (ticketId, senderId, message, isStaff)
- AuditLog (actorId, action, resource, ip, metadata)
- SecurityEvent (userId, type, ip, metadata)

# ARCHITECTURE DECISIONS

## Decision 1: Monorepo with Turborepo

Date: 2026-07-12

Reason: Shared code between apps, unified build pipeline, faster development

Solution: Turborepo + pnpm workspaces with apps/ and packages/ structure

## Decision 2: NestJS for Backend

Date: 2026-07-12

Reason: Enterprise-grade, modular, DI, TypeScript-first

Solution: NestJS with modular architecture (auth, users, vpn, payments, etc.)

## Decision 3: PostgreSQL + Prisma

Date: 2026-07-12

Reason: ACID compliance, mature ecosystem, excellent Prisma DX

Solution: PostgreSQL 16 with Prisma ORM and migrations

## Decision 4: Schema-first Prisma Design

Date: 2026-07-12

Reason: Comprehensive database design before implementation

Solution: Created 25+ models covering all VPN platform features

## Decision 5: Split Layout for Auth

Date: 2026-07-12

Reason: Premium feel, brand visibility on auth pages

Solution: Left panel with gradient + branding, right panel with form

## Decision 6: Argon2id for Password Hashing

Date: 2026-07-12

Reason: OWASP recommended, memory-hard, resistant to GPU attacks

Solution: Argon2id with 65536 memory cost, 3 iterations, 4 parallelism

## Decision 7: JWT with Refresh Token Rotation

Date: 2026-07-12

Reason: Stateless auth, scalable, industry standard

Solution: 15min access tokens, 7d refresh tokens, rotation on refresh
